# 分片路由与迁移语义

`strataleaf.ShardDatabase` 在保持集合/文档键 API 的前提下，把文档分布到多个独立的单文件 `Database` 分片。路由事实保存在独立的 `router.db`，与文档分片分离；分片文件仍为基线 `shard-<id>.db`。重新打开目录即恢复环、分片、迁移台账与跨片事务台账，不依赖进程内存。

## 环路由

键的归属是持久环定义的纯函数：对 `collection + NUL + key` 取 SHA-256，前两字节映射到 65536 个槽，环上每个分片有 256 个虚拟节点，槽归属其后第一个虚拟节点。扩片只向环追加虚拟节点，既有槽的坐标不变，因此旧拓扑写入的数据在分片数量变化后仍能定位。环定义按 epoch 不可变地存于 `rings` 表，`explain(collection, key)` 返回槽位、epoch、属主分片、实际服务分片与迁移台账，可逐键核对。

## 迁移状态机

`add_shard` 在单个路由事务内发布新环 epoch，并为每个易主键写入 `migration_ledger` 条目：`pending → migrating → migrated`（另有 `aborted` 预留）。已完成的上一跳在调度下一跳前移入 `migration_history`，多跳扩片不丢归属轨迹。

- `pending/migrating` 的键仍从源分片读，新环属主只在迁移完成后接管，因此扩片期间不存在两义读。
- 写路径遇到未完成条目会先惰性完成该键迁移，再在目标分片提交，保证写后读落在新属主。
- 迁移重放该键在源分片保留的完整版本链（含墓碑），逐版本以确定性 request key 提交；目标可见状态与逐版本 body/expires 核对一致后才清理源分片版本与索引投影。崩溃后重跑复用分片收据，不产生重复版本。
- `migrate_drain(limit=None)` 可分批推进，关闭重开后续迁；`migration_status()` 暴露各状态计数与完整条目，`verify()` 交叉核对环属主、台账状态与各分片物理键集合。

## 跨片读一致性

每个分片有独立的修订序列，不存在全局修订号。跨片查询向所有分片扇出、按键全局合并排序，并在返回清单（manifest）中显式说明一致性：

- 默认/首屏查询固定每片当前 head，清单标注 `per_shard_head` 或 `pinned_per_shard_revisions`，并给出每片修订号。它代表分片级一致的合并视图，不是跨片单点快照：不同分片可能在不同时刻取 head。
- 传入或经游标携带的每片修订映射（revisions）可复现确定的跨片读视图；扩片后旧清单缺少新分片会被 `InvalidCursor` 明确拒绝，而不是静默用新分片 head 补读。
- 单键读在其服务分片内保持基线的线性化语义；分页游标由路由库 HMAC 签名，绑定谓词、键边界与每片修订。

## 跨片批次

单分片批次沿用基线 SQLite 单写者原子提交。跨多分片批次无法做成单个 SQLite 事务，协调器因此在**任何写入前**执行 preflight：解析物理分片、校验集合存在与 `expected` 修订，任一冲突整批拒绝（`Conflict`/`NotFound`），不触碰任何分片。跨片批次必须携带 `request_key`，否则在 preflight 前以 `InvalidDocument` 拒绝。

通过 preflight 后，协调器把计划写入 `xact_ledger`（`prepared → partially_committed → committed`），再逐片以 `<request_key>:<shard_id>` 的幂等键提交，并在每片成功后更新台账。若某片失败，抛出 `CrossShardCommitError` 并携带已提交分片与每片修订；调用方用同一 request key 加相同操作重试，即跳过已提交分片、续提剩余分片。相同操作的重放直接返回收据、不再评估 expected 修订；request key 复用不同操作按 `Conflict` 拒绝。系统不提供自动回滚已提交分片的分布式回滚，承诺的是显式、可恢复、可核对的两阶段结果，而不是静默的部分成功。

集合创建是跨片 DDL 的同类事务：任一分片已存在同名集合则在任何 DDL 前失败，台账记录每片完成情况，可重试续建。

## 边界

分片内仍受基线全部约束（1–10000 操作、每批每键一次、模式、唯一索引、1 MiB 文档等）。环槽与虚拟节点数量固定，当前只支持加片，不支持缩片或自定义放置策略。协调器用进程内锁串行化拓扑变更、迁移与惰性迁移；多进程同时打开同一路由目录不在承诺内。跨片查询为全分片扇出合并，不保证常数内存或分片裁剪。每个分片保留独立修订历史；迁移复制保留的版本链，源分片在核对通过后才删除其物理副本。
